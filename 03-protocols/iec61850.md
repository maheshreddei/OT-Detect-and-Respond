# IEC 61850 (MMS / GOOSE / SV)

## Snapshot
| Property | Value |
|----------|-------|
| Port/transport | MMS: TCP/102 · GOOSE: L2 multicast (ethertype 0x88B8) · SV: L2 (0x88BA) |
| Purdue | L1–L2 substation automation (IEDs, protection relays) |
| Auth | **None** at protocol level (IEC 62351 adds security; uneven adoption) |
| Telemetry | ICSNPP-61850 / `mms.log`, **L2-tap** for GOOSE/SV, NDR, pcap |

## What it is
The substation-automation standard for electric utilities. Three sub-protocols: **MMS** (client/server over TCP/102 — read/write named variables, control operations), **GOOSE** (fast Layer-2 multicast event messaging between IEDs — e.g. trip signals), and **Sampled Values** (streamed measurement data). GOOSE and SV are **Layer-2, on the substation LAN** — not routed.

## What it really means for a defender
Two very different attack surfaces. **MMS** follows the familiar model — control operations (SelectWithValue/Operate on control objects) and writes are the impact events, recon is variable enumeration. **GOOSE** is the dangerous one: it's unauthenticated L2 multicast that IEDs *trust*, so a **spoofed GOOSE frame** with a higher state number (`stNum`) can override protection logic (e.g. force a trip or block one) — and it's only visible to a sensor on that physical LAN segment. Defensive priorities: MMS control/write from non-SCADA sources, and **GOOSE anomalies** — unexpected `stNum`/`sqNum` jumps, GOOSE from an unexpected source MAC, or GOOSE appearing where it shouldn't. This requires station-bus visibility you must deliberately provision.

## Attacker actions (recon → impact)
- **Discover/recon (MMS):** connect on TCP/102; enumerate the data model (logical devices/nodes, named variables).
- **Write (impact, MMS):** write named variables; perform control (SelectWithValue → Operate) on a control object.
- **Spoof (impact, GOOSE):** inject GOOSE frames with incremented `stNum` to force IEDs to act on a false state (trip/block).
- **Disrupt (SV):** inject/alter sampled-value streams to corrupt protection inputs.

## Detections you can build
| Detection | Signal / logic | Log source | ATT&CK ICS |
|-----------|----------------|------------|------------|
| MMS control Operate from non-master | Control (Operate) on a control object from outside SCADA baseline | `mms.log`/ICSNPP-61850 | T0855 Unauthorized Command Message, T0831 |
| MMS write to named variable | Write service to critical variables | `mms.log` | T0836 Modify Parameter |
| GOOSE stNum/sqNum anomaly | Out-of-sequence or jumped state number (spoofing signature) | L2 capture / ICSNPP-61850 | T0856 Spoof Reporting Message, T0832 |
| GOOSE from unexpected source | GOOSE with unknown source MAC / on wrong segment | L2 capture | T0856 |
| Sampled-Values rate/quality anomaly | SV stream rate or quality deviates | L2 capture | T0856 |
| MMS data-model enumeration | Bulk model browse from new client | `mms.log` | T0846 |

## Log sources & telemetry
MMS: ICSNPP-61850 / `mms.log` over TCP/102 (routed, visible to a normal tap). **GOOSE/SV need a Layer-2 tap on the station bus** — they don't cross routers, so a north-of-boundary sensor is blind to them; place a sensor on the process/station LAN. NDRs with 61850 support parse GOOSE stNum/sqNum for spoof detection. pcap on the station bus is the ground truth for GOOSE injection.

## Functions/services to watch
**MMS:** read/write named variables; **control** services (SelectWithValue, Operate, Cancel) on control objects; data-model browse (recon). **GOOSE:** `stNum` (state — jumps = event/spoof), `sqNum` (sequence), source MAC, `goID`/dataset. **SV:** sample count/rate, quality flags.

## ATT&CK mapping
T0855 Unauthorized Command Message · T0831 Manipulation of Control · T0836 Modify Parameter · T0856 Spoof Reporting Message · T0832 Manipulation of View · T0846 Remote System Discovery.
